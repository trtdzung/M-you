## Required execution order

1. **Characterize current code paths and tests.** Keep `POST /api/proactive-insights/current` and `HomeInsightWidget` compatible. Confirm which Home service is active before changing persistence.
2. **Add a pure Health Score contract and scoring module.** Centralize/version thresholds; track score coverage; preserve `null` and source provenance.
3. **Complete one vertical slice:** jar pressure through deterministic candidate → dispatcher/cache → current Home API/widget, with regression tests.
4. **Add only data-supported insight rules.** Follow each rule's `ACTIVE`/`PARTIAL`/`BLOCKED_DATA` status and required evidence.
5. **Unify dispatcher/persistence only through a deliberate migration.** Do not create a third parallel path. Maintain API compatibility or update producer, route, consumer and tests together.
6. **Update architecture, data readiness and implementation notes** only to reflect behavior actually shipped.

## Release gate

No implementation is complete until the targeted tests, full test suite, build and lint outcomes are recorded; unsupported rule families remain disabled; no financial number is generated by LLM; and the current Home widget still works for success, empty, loading, error and dismissal cases.
